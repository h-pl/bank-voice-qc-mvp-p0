# 播放指针连续更新

问题：原指针随 timeupdate 触发 React 更新。本地实测约 1.2 秒有 73 个显示帧，但只有 4 次 timeupdate / 5 个指针位置，产生跳动。

实现：使用 requestAnimationFrame 读取 HTMLAudioElement.currentTime，直接通过 transform 更新指针、clip-path 更新已播放波形。显示帧不触发 React 或转写重绘，原 Slider 保留拖动、键盘和读屏语义。无基于墙钟推算、CSS 缓动或补间，因此暂停、缓冲和倍速不导致视觉进度自行漂移。命中高亮仍代表整段证据，不作为播放进度填充。

播放/seeked 启动单个帧循环；暂停、结束、等待、错误和卸载取消。拖动、键盘及原话定位同时立即刷新视觉；timeupdate 继续同步时间文字和转写。隐藏页面仍沿用原暂停行为。减少动态效果模式保留必要的真实媒体位置，无附加动画。

验证：
- 修复后初次测量：约 1.2 秒 / 73 帧中有 67 个不同位置，2 倍速为 73 个；起播时音频时钟尚未前进的帧不会伪造位移。
- 暂停后等待 300ms 指针和音频时间均不变；定位16秒显示40%，鼠标拖动到75%为30秒，保持暂停。
- 键盘 Home/方向键保留，播放轴有可见焦点；减少动态效果及390px宽度检查正常。
- 新增4项回归测试覆盖稀疏timeupdate、暂停定位、缓冲/倍速/结束、卸载清理；与原时间轴3项测试共7/7通过。
- TypeScript、ESLint、生产构建通过。未测所有浏览器或高负载设备帧率。

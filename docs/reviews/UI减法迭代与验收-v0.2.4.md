## 角色边界

| 角色 | 申诉 | 整改 |
| --- | --- | --- |
| 客服坐席 | 从本人质检结果提出申诉、补证、撤回并查看裁定 | 接收要求、执行、提交本人材料 |
| 质检员 | 在质检工单完成指派的核查并提交意见 | 在申诉与整改验收指派任务及核对补件 |
| 质检主管 | 受理、分派核查、裁定、协调补证 | 下发/调整要求，依据验收结果结案或退回 |

申诉与整改共用入口，属于不同对象；按权限与当前责任过滤待办。申诉期间的整改暂停、恢复、终止仍使用原业务逻辑。没有增减角色或指标。

## 设计与验证

使用 frontend-design、web-design-guidelines、vercel-react-best-practices、animate；先写设计约束再实现。参考 [Web Interface Guidelines](https://raw.githubusercontent.com/vercel-labs/web-interface-guidelines/main/command.md) 的标题、可访问标签、焦点和减少动态效果要求。维持现有灰白橙黑视觉，优先移除重复信息和层级。

- 类型检查、lint、生产构建通过；57 项业务/报表回归全部通过。
- 1440×1000 与 390×844 七个模块没有整页横向溢出；申诉整改最终窄屏另行检查。
- 账户查询筛选与重置、三角色导航、申诉/整改类型筛选、申诉自跳转修复通过。
- 规则静默阈值 15 改为 20 后取消，仍为 15；16 项指标目录支持 Escape 并恢复触发按钮焦点。
- 报表日期钻取为 5 条，打开事项后返回，日期范围和 5 条明细保持。
- 1440×1000 风险预警业务面板顶边从 295.625px 前移至 89px，主要内容提前约 207px。

本轮是 UI 结构及导航修正。没有逐个重新执行所有业务动作；流程逻辑使用既有 57 项回归。仍为虚拟数据高保真原型。

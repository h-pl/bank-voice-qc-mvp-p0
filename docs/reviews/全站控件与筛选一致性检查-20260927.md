# 全站控件与筛选一致性检查 · 2026-09-27

目标：质检-ui-6001，本地 6001 网站。

## 依据和范围

检查 app 与 components 的 TSX、components/ui 实现、页面 CSS 覆盖及全站重置入口。对照官方 [Input](https://ui.shadcn.com/docs/components/input)、[Select](https://ui.shadcn.com/docs/components/select)、[Combobox](https://ui.shadcn.com/docs/components/combobox) 结构和当前项目 shadcn new-york 配置。保留项目 Radix 基础以及已有 Base UI Combobox，不为外观统一引入新框架。

源码扫描覆盖 67 个 TSX 文件、23 个 ui 基础组件文件；排除基础组件内部实现后，业务组件没有直接使用原生 input/select/textarea/button。隐藏音频文件选择器也已改用 Input。原生 label、table、语义区域以及图表不等于控件不合规。

## 发现与处理

| 项目 | 发现 | 处理 |
| --- | --- | --- |
| 输入及搜索 | 页面覆盖导致 2px/3px 光圈、边框色不一致 | 统一状态文件，SearchField 改用 InputGroup；只在外框显示焦点 |
| 下拉与日期 | 打开时缺少一致反馈，局部样式压过基础 focus | SelectTrigger、DatePicker 统一打开/聚焦状态；保留 Radix 键盘行为 |
| 多选 | 使用 shadcn Base UI Combobox 组合 | 与普通输入共用外框状态，内部 chip input 无第二层边框 |
| 错误/禁用 | 全局 input 与各页覆盖规则混杂 | aria-invalid/user-invalid 使用红色；disabled 浅灰面和灰字，错误优先于普通 focus |
| 重置按钮 | 报表文字按钮与列表描边按钮不一致；逾期未清除 | 共用 outline 按钮；筛选后才显示；清除全部当前筛选，报表回默认近7天 |
| 重复信息 | 预警、申诉整改工具栏重复总数；申诉整改重复筛选标签行 | 删除指定重复区，数量保留页签/队列标题 |

## 组件结论

- Input、Textarea、Select、Button、Dialog、Popover、Checkbox、Switch、Tabs、Tooltip、Slider 等来自或组合自项目 components/ui；SelectField 是 Radix Select 业务封装，保留 option 调用格式但不渲染原生 select 作为可见控件。
- Calendar/DatePicker 使用 react-day-picker + shadcn Popover/Button/Select；Combobox 使用现有 shadcn Base UI 实现。
- 队列卡片、图表、业务详情、信息提示条和页面 toast 为业务自定义组件，不宣称是 shadcn 原版；toast 保留 role=status/aria-live，业务卡片的点击入口复用 Button。
- 本轮进行全量源码检查及代表场景浏览器验收，不等于逐个业务保存流程全部回归；没有修改业务数据或执行业务保存。

## 验证

已通过生产构建/TypeScript、改动文件 ESLint。实际检查：申诉整改的业务/关键词筛选与重置、逾期重置、风险预警重复计数删除、通话高级筛选重置及搜索清除、资源搜索重置和关键词编辑弹窗 Input/Textarea 焦点、策略重置、报表业务/日期错误与恢复。搜索和 Select 实测同为橙色边框及 3px 光圈，内部输入无重复阴影；报表日期错误显示红框且重置后错误解除。窄屏 390px 检查筛选栏重排。

最终位置验收：预警页无筛选时不渲染重置按钮；选择信用卡后按钮出现在业务选择器右侧（桌面间距12px），右侧保留仅看逾期与导出。390px窄屏按行重排，重置后恢复全部业务且按钮消失。

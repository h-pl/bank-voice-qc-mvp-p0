# 研发方案与部署评审

> 2026-09-12 范围澄清：当前交付物为高保真原型，模拟数据、预设结果与前端状态均可使用。本文涉及真实模型、后端、客户验收及容量实测的内容为未来交付参考，不作为本轮原型完成条件；当前仅检查页面、交互、业务流转与示例一致性。

本文件整合[原部署方案](archive/docs/官方指标缺口补齐与最小部署资源_V1.md)和[三文档评审](重要资料三文档评审_20260910.md)，保留项目已有的质量优先路线。这里记录的是设计与证据要求，不是新增硬件采购建议或生产容量承诺。

## 1. 证据分层

| 层次 | 当前材料能说明什么 | 不能推导什么 |
| --- | --- | --- |
| 静态代码/页面 | 能定位部分检测、结果结构与演示交互 | 不能证明效果、长通话覆盖、并发或完整业务闭环 |
| 仓库实验 | 对指定模型、数据集、机器及脚本的局部结果 | 不能外推银行客户数据、全部情绪类型或目标生产环境 |
| 工程方案 | 补齐路径、服务拆分、候选模型和资源起点 | 不能标为已经实现或正式验收通过 |
| 客户验收 | 应具备冻结集、真实服务、完整运行与目标环境证据 | 当前尚缺，不能由前三层替代 |

研发报告的“完整 10、部分 4、未支持 2”按静态支持盘点理解，与规则页 10 类没有对应关系。相邻 `zhijian-qc-1.0.0` 归档未被证明与报告引用的 `playground/voice-qc` 为同一提交；源码发现只对已查归档成立。

## 3. 沿用的技术路线

| 能力 | 设计路线 | 关键验证 |
| --- | --- | --- |
| 声纹识别 | 原方案候选为 3D-Speaker 的 ERes2NetV2/CAM++，独立注册与验证服务 | 授权、音质、注册/测试隔离、FAR/FRR 与难例 |
| 文本纠错 | 神经纠错结合领域词典和实体保护，原始转写与修订版本并存 | 召回、误改率、金额/账号/产品等关键实体不可误改 |
| 覆盖率 | 任务台账、队列、Worker、失败与重试账本 | 应处理清单核对、漏跑与重试可追溯、幂等 |
| 时效性 | 原方案使用 OpenTelemetry 等链路追踪方案，记录统一时间边界 | 实时/离线分开统计全链路分位数、超时与故障 |
| 专业性 | 版本化知识，BM25 与向量检索，重排后由较大模型核验事实/SOP；关键数值用确定性校验 | 引用可追溯、知识时效、事实错误、证据不足转人工 |
| 隐私性 | 正则与词库、NER/UIE、角色及上下文判断，结合脱敏与必要语义复核 | 分类型泄露召回、误报、证据、脱敏和权限分别验证 |

专业性保留原方案的 embedding 4B、reranker 4B、14B 核验模型规模设想及三类资源池设计。具体模型、量化、上下文长度和部署版本须由项目冻结集与目标环境测试确定。RAG 是本项目工程选择，不是标准指定算法；减少模型或资源需要质量与负载证据。

对知识缺失、依据冲突、模型失败和证据不足统一表达“不确定/需人工确认”，不能强行给出合规或不合规结论。检测隐私风险与保护数据访问、脱敏、留存是不同交付项。

## 4. 容量评审

原方案以实时 16 路并发并叠加离线任务作假设，提出两张 48 GB 加一张 80 GB GPU、32 vCPU、128 GB 内存、2 TB NVMe 等工程起点；这不是已验证的最小生产规格。原归档约 24.5 GB 模型占用也不能直接代表整套目标系统显存需求。

容量表至少登记实时并发、平均时长、分段频率、语义触发比例、专业核验次数、离线峰值、音频码率、日通话量、留存、存储副本、事件写放大和目标利用率。三类 GPU 资源池与网关、队列、业务库、检索、对象存储、监控分别核算。

在同一模型/硬件/批次/上下文配置下测得单副本能力后，才可计算候选副本数：

`副本数 = ceil(峰值需求 ÷ 单副本实测吞吐 ÷ 目标利用率)`

计算还需满足所选部署档位的冗余要求。缺少实测吞吐时保持“待压测”；有单池结果后仍须做实时、离线、查询及回听同时运行的混合压测。

进入生产规格评审至少需要五类证据：客户生产负载、冻结集质量、三池实测、全链路混合压测、故障恢复演练。界面填入报告编号只表示登记，需校验报告内容、版本与审批，不自动等于通过。

## 5. 接口与交付闭环

生产链路须实现真实接入、任务持久化、异步任务 ID、失败/重试/幂等、服务端权限、追加审计、规则与资源版本、通知送达及业务统计。人工意见不能覆盖自动证据，服务不可用不能自动判阴性。

研发交付按“指标 → 被测服务版本 → 数据/金标版本 → 运行结果 → 目标环境 → 遗留问题”提供证据包。16 项准备和验收逐项记录，见[指标专题](16项指标与规则配置及验收.md)；前端本地状态演示与真实后端实施分开跟踪，见[版本与验证现状](版本与验证现状.md)。

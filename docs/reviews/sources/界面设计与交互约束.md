# 界面设计与交互约束

本文件收敛根目录 DESIGN、UX-CONTRACT 中仍有效的界面规范。产品范围、角色权限、状态流转分别由[产品需求](产品需求_当前评审版.md)和[主管分诊流程](银行呼入客服质检主管分诊细化流程.md)维护；本文件不再重复旧 SaaS 规则创建流程。

## 1. 视觉与布局

采用密集型 B 端控制台：浅灰画布、白色内容面、细边框、低圆角；橙色用于焦点与证据，黑色用于主要动作，绿色表示完成或健康，红色表示高风险或阻断。状态同时有文字，不依赖颜色。

| 语义 | 设计基线值 | 运行时维护位置 |
| --- | --- | --- |
| 画布 | #F7F7F7 | app/globals.css，--canvas |
| 内容面 | #FFFFFF | --surface |
| 正文 | #171717 | --ink |
| 次要文本 | #6F6F6F | --muted |
| 边框 | #E5E5E5 | --border |
| 强调 | #F47B34 | --accent |
| 成功 | #118447 | --green |
| 警示 | #C96821 | --warning |
| 危险 | #BD3038 | --danger |
| 信息 | #2D6FBD | --info |

以上保留原设计基线，实际样式仍由 CSS 维护，本次未逐条重验所有 CSS 覆盖。字体沿用 Inter / PingFang SC / Microsoft YaHei；编号、版本、时间和指标使用等宽字体。原设计参考值为正文 14 px、页面标题 28 px、面板标题 15 px、圆角 8–16 px，按具体组件和响应式布局应用。

桌面固定侧栏和顶栏，平板/窄屏切为抽屉导航；表格可横向滚动，主要动作始终可访问。原侧栏 236 px、顶栏 64 px、内容最大宽 1500 px 是设计参考，不作为本次已验证的所有页面尺寸。

## 2. 页面骨架与证据阅读

- 客户生产台采用固定导航分组及页面名称，权限裁剪无关入口。顶栏通知独立于左侧业务导航。
- 风险预警、质检工单、申诉整改使用队列内分类 Tab、详情与当前动作；通话记录保留日志表格。工单布局变体复用业务状态，不能各自创建状态机。
- 风险预警优先展示实时转写、命中话轮与可回听原音；规则、指标、检测器和版本链可展开查阅，不能抢占对话首屏。
- 工单详情聚焦事实、证据、当前责任人、下一动作及已经发生的事件。预测下一步与历史分开，种子快照不能伪装成真实操作记录。
- 申诉回答原结论是否正确，整改回答行为是否改善；页面可关联追溯，但不能混合状态含义或完成率。

## 3. 组件与操作

| 组件 | 统一约束 |
| --- | --- |
| 选择框 | 原生 select，接受系统弹出层几何差异；键盘可用 |
| 日期 | 原生 date，ISO YYYY-MM-DD 值；期限须通过业务校验 |
| 操作表单 | 复核、参数申请、资源导入、标注等用上下文表单；提交前校验，成功后同步状态 |
| 弹窗 | 支持退出、Escape、焦点圈定与关闭后恢复焦点；窄屏可滚动 |
| Toast | 仅作回执；必须与真实发生的业务变更一致 |
| 通知 | 来源、对象、类型、摘要与跳转明确；已读不等于完成业务任务 |
| 状态徽标 | 文字与视觉标记并用；严重度、生命周期、评测状态分别解释 |
| 列表详情入口 | 整行热区、悬浮反馈和键盘焦点一致；返回保留分类 |

加载期间保留原视图并显示忙碌状态。失败、未知、未检测必须与正常未命中区分。无权限或非当前责任人的记录只读，说明等待谁处理；正式权限由服务端控制。

客户规则页面仅调整项目开放的参数，不能出现创建/删除/AI 改写规则结构的入口；我司新增规则属于项目变更。资源内容可授权维护新版本，提交、审核、回归与生效有独立事实记录。

## 4. 验证与维护

界面检查应覆盖键盘、弹窗、空队列、角色切换、通知定位、刷新和窄屏。状态提交后核对列表、详情、责任人、待办和时间线。规则、指标、资源从统一目录读取，不各自维护名称与映射。

已做验证与尚未验收的部分见[版本与验证现状](版本与验证现状.md)。历史视觉报告与截图归档保存，不能用于宣称当前页面全部通过。

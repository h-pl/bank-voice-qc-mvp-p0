# 产品需求：当前评审版

> 2026-09-12 范围澄清：当前交付物为高保真原型，模拟数据、预设结果与前端状态均可使用。本文涉及真实模型、后端、客户验收及容量实测的内容为未来交付参考，不作为本轮原型完成条件；当前仅检查页面、交互、业务流转与示例一致性。

整理日期：2026-09-11。适用范围：银行呼入客服质检私有化项目。代码参照 `v4.11.0-private.1`，流程细化含待实现项，见[版本与验证现状](版本与验证现状.md)。

本文整合旧 PRD 的有效要求，并消除版本间冲突；它是后续评审的主入口。原始字段示例和历史演变仍可通过[归档清单](历史文档阅读与归档清单.md)追溯。

## 1. 产品目标与范围

从一通电话追溯到原音、转写、候选风险、规则版本、人工结论、申诉、整改与评测证据。自动检测只产生候选风险；不能直接认定违规或生成处罚结论。

产品分为两个工作面：

- **客户生产台**：日常通话查询、风险分诊、人工复核、申诉整改、固定规则参数、业务资源、质量报表、客户系统管理。
- **我司项目后台**：能力与部署、检测资源、测试集与标注、验收评测、交付与运维。

当前为一个客户项目的私有化实例，不提供 SaaS 多租户切换。保留 16 项完整指标体系；规则配置展示其中 10 类业务判断或处置流程，另外 6 项由能力服务及平台验收承接。

## 2. 角色与责任

| 工作面 | 角色 | 主要责任与边界 |
| --- | --- | --- |
| 客户 | 运营负责人 | 看趋势、SLA、重复问题与督办；不改写专业结论 |
| 客户 | 质检主管 | 候选风险分诊、人员分派、确认结论、受理申诉、下发整改及关闭 |
| 客户 | 质检员 | 按任务回听复核、提供意见与证据；独立进行整改效果复测，意见交回主管 |
| 客户 | 班组长 | 承接整改、安排坐席、辅导及材料完整性核验；不替代质检正式验收 |
| 客户 | 客服坐席 | 查看本人结论、接收提醒、提交正式申诉及整改材料 |
| 客户 | 业务/合规专家 | 按主管分派核对规则与业务边界，返回裁定或补证意见；受控维护业务资源 |
| 客户 | 系统/安全管理员 | 组织权限、接入及安全管理；敏感资源另行授权，不能因管理员身份自动获得全部内容 |
| 我司 | 项目经理 | 组织交付、客户材料、项目变更、验收包与问题闭环 |
| 我司 | 模型评测工程师 | 检测资源、冻结集、服务评测、错误分析和回归 |
| 我司 | 交付运维工程师 | 接入部署、容量验证、监控恢复及运行证据 |

每次可执行动作需同时满足角色、数据范围、当前责任人与当前状态。原型的角色切换用于演示，生产权限必须由 SSO/IAM 与服务端执行。

## 3. 页面与业务对象

客户导航分组和名称保持稳定；角色只裁剪无关入口、数据范围与动作。

| 分组 | 页面 | 承接内容 |
| --- | --- | --- |
| 工作区 | 工作台 | 当前角色待办、风险与阻断项 |
| 质检作业 | 通话记录 | 历史通话查询、原音、转写和关联记录 |
| 质检作业 | 风险预警 | 系统候选风险和主管三路分诊 |
| 质检作业 | 质检工单 | 分诊后的人工/事后复核、专家意见、主管确认 |
| 质检作业 | 申诉与整改 | 独立申诉案件与独立整改案件，两种状态机分开 |
| 策略与资源 | 规则参数 | 已交付规则的白名单参数调整 |
| 策略与资源 | 业务资源 | 授权范围内的知识、词库、标签、SOP、声纹版本 |
| 分析与管理 | 质量报表、系统管理 | 业务统计、组织权限和系统配置 |

顶栏通知中心聚合各模块的待办、提醒、结果；通知携带具体业务对象与事件标识，点击后进入对应模块，不在通知内另建业务状态。打开或标记已读不代表任务完成。

“质检工单1/2/3/4”是原型布局比较版本。当前迭代重点为工单4，多个页面复用同一业务对象和动作校验；不因多一个页面而增加业务状态。旧版把风险、申诉、整改全部混入一个工单详情的设计不再作为当前页面范围。

## 4. 证据与状态契约

| 对象 | 必须保留的信息 |
| --- | --- |
| 通话 | 通话编号、来源、角色/声道、起止时间、录音与转写版本、业务字段 |
| Finding | 候选风险编号、通话、主指标、关联指标、触发规则、检测器与资源版本、检测状态 |
| Evidence | 原音位置、时间范围、说话角色、转写及上下文、引用依据和版本；模型理由不能替代原音 |
| 复核任务 | 来源风险、分派人、当前责任人、复核要求、期限、意见与最终结论、状态版本 |
| 申诉案件 | 原结论、申诉人、受理与裁定记录、补充材料轮次、关联整改、窗口和送达记录 |
| 整改案件 | 来源结论、责任班组/坐席、整改目标、期限、完成标准、材料、复测样本与轮次 |
| 事件 | 业务对象、前后状态、操作者及角色、时间、理由、证据版本、责任人变化与关联通知 |

业务对象通过关联编号追溯，不能因为共用索引就合并风险、复核、申诉、整改的状态含义。每个活动阶段明确一个当前责任人；补证执行人可单列。事件、人工意见和材料按版本追加，原始自动结果不可覆盖。

通话结束事件、重复提交和通知重试需要幂等；状态、责任人、待办、SLA 与事件须在服务端一致更新。逾期是由期限计算的标记，不单独改变生命周期或自动关闭。

## 5. 核心业务链路

完整节点、分支与关闭条件以[主管分诊细化流程](银行呼入客服质检主管分诊细化流程.md)为准。

1. 系统创建候选风险，主管执行“误报或证据不足”“转人工复核”“通话中提醒坐席”三条一级路径。观察、补证在路径内部完成，不增加一级按钮。
2. 误报关闭与证据不足关闭分别存原因；观察必须有责任人、期限和复查条件。证据不足不能统计为已证实误报。
3. 提醒只在通话中使用，不等于最终结论。通话结束后自动准备事后复核；沿用有效分派，缺失或失效时由主管补齐。提醒回执和提醒异议不阻塞通话结束事件，也不取消事后复核。
4. 质检员或专家将意见返回主管。质检员可以建议转专家，由主管决定并转交；补证仍需有责任人与回流，不能停在一个无出口节点。
5. 主管确认误报或证据不足时记录相应结案原因；确认风险成立时判断是否需要整改。**成立但无需整改**应保留成立结论、理由与证据，结案并保留申诉入口，不能伪装为误报。此出口为本轮流程细化，V4.11 尚未实现。
6. 确需整改时，主管一次填写责任班组、目标、未来期限与完成标准，提交即创建待班组签收案件并结束对应复核工单，不再额外生成待下发草稿。

正式申诉由坐席发起，班组长可协助整理材料；代提交需要明确授权。主管受理后，事实问题交质检员复核、规则或业务边界交专家，意见与补件经主管回流。申诉处理中冻结关联整改的 SLA 计时并禁止关闭；裁定后按结果恢复或终止，保留原期限及冻结记录。维持原结论不自动意味着必须新增整改。

整改由班组组织、坐席执行，班组核验材料完整性；质检员进行每轮唯一正式验收，主管按结果关闭或退回。模拟演练可用于预检查，不能替代真实生产样本的效果验收；样本不足时保留待验证状态与责任人。以上细化与当前实现的差异集中列于版本文档。

## 6. 规则参数与业务资源

客户不得新增、删除或改写规则逻辑、主指标、检测器编排或证据契约。可调整的阈值、适用范围、时间及处置去向，限于项目交付明确开放的 Schema 白名单；参数变更需要审批、影响分析、回归运行与版本记录。

规则结构固定不等于资源不可维护。知识、词库、情绪/意图标签、SOP 和声纹资源允许授权角色提交新版本，经过解析校对、重复/冲突检查、责任部门审核及受影响规则/服务回归后，才能切换生产引用。一个资源可以关联多个指标；一条规则只有一个主指标，关联指标用于检索与影响分析，不重复计分。

规则可以组合关键词、正则、语义模型、声学时序、知识核验与确定性校验。旧 SaaS 文档的客户自助创建/AI 编排规则入口不属于当前客户权限；新规则进入项目变更。

声纹注册、原音、特征与身份映射单独授权，记录采集授权、音质、同一性、版本、留存及删除策略；页面可录制不代表后台授权与识别能力已经交付。

## 7. 评测、统计和交付

16 项目录和验收要求见[指标专题](16项指标与规则配置及验收.md)。Gold 由独立标注和专家仲裁产生，Prediction 来自冻结版本的真实被测服务；人工复核样本先进入金标候选池，不能自动成为 Gold。

普通业务页面显示风险、证据、任务和业务结果。测试集、验收公式、混淆矩阵、技术版本和部署证据由我司专业页面及报告承接；客户端隐藏字段不能替代接口权限裁剪。

报表至少区分候选风险、人工确认风险、误报、证据不足、申诉结果与整改结果。关闭复核不代表风险不成立，申诉关闭不代表整改完成；不同对象不能混用分母。按时完成率要明确使用“期间到期任务”还是“已关闭任务”作为分母，并同时披露未关闭逾期，不能让尚未关闭的积压消失。

交付应包含版本化接入契约、任务台账、失败/重试记录、真实权限、评测结果、容量与恢复证据。质量优先技术路线及验证要求见[研发专题](研发方案与部署评审.md)。原型中的 Toast、示例报告、容量输入和资源登记不能当作这些能力的完成证明。

## 8. 页面交互约束

风险、工单和案件使用队列内分类 Tab、证据详情、当前责任与下一步动作；通话记录保留日志表格。空队列必须仍能切换分类。动作提交后列表、详情、角色待办、通知和事件时间线同步变化；非当前处理人显示等待对象与只读原因。

历史时间线只显示已经发生的事件，下一步预测单列。错误或服务不可用显示明确状态与补救，不把失败视为未命中。表单保留校验、取消、键盘焦点及窄屏可操作性；视觉变量与布局细节参照[界面设计与交互约束](界面设计与交互约束.md)，冲突业务说明以本文及流程专题为准。

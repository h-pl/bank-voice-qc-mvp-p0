## 构造方式

使用真实业务命令生成 31 组场景：先有通话及检测，再有预警分拣、复核、坐席选择、申诉或整改。人工状态、意见、材料、轮次和历史由对应操作生成，未提交字段保持为空。普通复核按单个预警办理；同通话只关联展示，不能合并成无来源的综合工单。

工单 WO-1039 对应“出现消极服务表达”，WO-1039-B 对应“未完整说明处理时限”：同一通话，前者复核为非误报待主管确认，后者仍核实业务依据且尚无正式意见。

## 字段与动作

| 字段组 | 实现与存储 | 产生约束 |
|---|---|---|
| 预警策略判断 | warningDecisions.result / conditions / policyVersion | 检测结果按已发布策略判断；满足才产生 Finding |
| 预警处理状态 / 分拣方式 | Finding.status；Event.action | assign / dismiss / dispatch 后变化 |
| 工单类型 / 办理状态 | Review.type / status / owner / dueAt | 由预警、人工抽检、申诉入口创建 |
| 复核结论 | Review.opinions / history | submit_review：误报 / 非误报；证据不足保持核实中 |
| 抽检结果 | Review.scopeResult / summary / findingIds | 未发现问题为 clear，不新增问题或误报档案 |
| 主管确认结果 | Conclusion；Review.history；Event | publish / return；保留质检员原意见 |
| 分发来源 / 坐席选择 | Finding.distribution.source / status / at | direct / review / spotcheck 自动产生；待选择不等于接受 |
| 申诉办理 / 资料判断 | Appeal.status；Review.evidenceRequest；Supplement | 提交、指派、补件、核查；保留原结果版本 |
| 申诉核查 / 审核 / 回应 / 裁定 | Review.opinions / history / supervisorComment；Appeal.outcome | 质检员建议与主管裁定分开；赞同回核查，不赞同补充说明 |
| 整改来源 / 核验人 | Remedy.origin / inspector；Finding.distribution | 接受或申诉不成立后进入；仅直接分发且接受可暂未指派 |
| 整改状态 / 核验结果 | Remedy.status / materials / acceptance | 资料可先提交；pass / fail 对应满足 / 不满足要求 |
| 整改审核 / 回应 | Remedy.supervisorComment / supplementRequirements / rounds | 赞同退回开启下一轮；不赞同保留本轮资料再次审核 |
| 办结类型 | 按 Finding / Review / Appeal / Remedy 实际终点派生 | 误报归档、抽检未发现问题、申诉成立、整改完成不互相冒用 |
| 批次 / 版本 / 证据 | Batch.ruleVersions / policyVersions / resourceVersions；detectionResults；Conclusion | 固定命中时快照；失败与未命中分开，人工意见不修改检测执行结果 |
| 责任与幂等 | Supplement / Event / Request / rev | 每个操作通过现有 apply 命令生成状态及事件 |

## 采纳映射

| 建议 | 本次实现 | 代码边界 |
| --- | --- | --- |
| 轻量工作台 | 当前身份待办、逾期、24h 到期、授权范围内最近变化；点击回原业务对象 | Workbench；复用 notices/canSee/primaryAction |
| 菜单统一、业务布局分别设计 | 新增工作区；工单明确为复核工单；保留风险、申诉整改、通话、规则、资源、报表独立职责 | nav + Home；三角色八入口 |
| 资源分类表格 | 业务知识/词库/SOP 分类；搜索、状态、分页；名称打开预览，详情用于完整核对 | ResourceCatalog，复用 Tabs/SearchField/Pagination |
| 按操作规模选择容器 | 资源快速阅读为右侧抽屉，完整资源编辑为独立页面；规则参数仍就地编辑 | Modal.resource、InlineFormSurface、Strategy.detailOnly |
| 减少办理页滚动 | 复核意见提前，去掉复核摘要中重复的来源编号与尚未形成结论；责任与动作从顶部对齐 | 共用 Detail / CaseResponsibility / case-shell |
| 材料能看懂 | 结论依据、申诉理由、整改交接、完成材料、验收意见逐项显示摘要/版本/待补状态，逐条预览 | CaseDocuments，原始数据及绑定版本不改写 |
| 当前责任及后续去向 | 显示当前处理人、阶段、期限及分派/核查/验收后的去向 | currentOwner + nextResponsibility；动作仍由 actions 决定 |
| 资源发布与规则采用分离 | 发布只新增资源版本；明确勾选规则并填写说明后切换引用 | resource-publication.ts + apply；逐规则 rev，原子性，日志，幂等 |
| 空结果可恢复 | 资源空列表可重置，报表空时段可恢复到有数据日期段 | 共用 Empty；保留业务筛选优先恢复日期 |
| 设计语言一致 | 沿用灰白橙黑 token、共享按钮、标签、页签、筛选、弹窗和焦点行为 | DESIGN.md、UX-CONTRACT.md、workspace-system.css |

资源切换对存在参数草稿、过期规则 revision、过期资源 revision、未选择规则、无权限身份均拒绝；一次选择中任何规则冲突时整体失败。成功仅对被选规则追加版本，其余规则和已开始检测保留原快照。没有新增审批流程或真实模型检查。

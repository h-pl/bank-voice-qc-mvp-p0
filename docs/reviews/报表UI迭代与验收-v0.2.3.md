## 1. 实际对比与设计取舍

浏览器实读 [线上 API 控制台](https://moss-api-enterprise-console.vercel.app/?view=keys)、4001 的 Key、用量与费用视图，以及 5001 原报表。前两者当前呈现相同设计：统一摘要区、明确数值层级、图表与明细分区、选择状态清楚；原报表以数字卡和长表为主，四视图同质，问题条形图缺少直接钻取。

采用 b2b-vibe-prototype、frontend-design、web-design-guidelines、vercel-react-best-practices。设计先写入本轮工作稿，再实现。保留灰白橙黑品牌，画布调为 #F6F7F8，通用面板 10px 圆角，标题 27px；报表摘要 30px、分区标题 15px、说明 12–13px、等宽数字。图表以橙色表达选择/数量，绿红表达状态，灰色表达待处理或无样本。不引入渐变、大面积装饰、额外动画或新的图表依赖。

布局为：页签 → 常显筛选 → 摘要与图形分析 → 相关指标 → 同口径明细。相比 API 累计费用曲线，本项目趋势按通话结束日汇总，不复制累计或付费语义；没有历史快照不生成环比，没有评分规则不生成绩效排名。

## 3. 数据与实现约束

`lib/reports.ts` 继续定义当前统计口径，未修改公式。新增 `lib/report-visuals.ts` 从这些记录派生趋势、分类与坐席矩阵，页面只保存语义选择，不复制数据快照到组件状态；对象更新后重新派生。Map / Set 核对对象关系，矩阵上限只计算一次，使用单一时钟订阅。图形使用原生 SVG 和可聚焦按钮，未增加 chart 库、请求链或模拟网络服务。

趋势最多 31 个连续日期段；比例按本段分子/分母计算，无分母留空，过去无记录的数量为 0，未来日期留空。成立和误报趋势按通话结束日期，使用当前结论重算，不能理解为当日历史快照。构成图包含自动和人工来源，误报占比仍只使用已明确判定的自动候选。

当前积压不受日期限制，仍受业务/班组/坐席范围限制；期间裁定按裁定日、按时办结按有效到期日。矩阵与坐席通话量只做事实核对，不表达绩效排名。0 单元格可查看空明细，所有导出按选中记录全集，不局限当前页。

## 4. 验证结果

- `pnpm typecheck`、`pnpm lint`、`pnpm build` 通过；最终构建内 TypeScript 再次通过。
- `pnpm verify:mvp` 57/57：原有 50 项加 `scripts/report-visuals.test.mjs` 7 项；覆盖日界线、加权比例、长日期段、空/未来日期、分类矩阵守恒、过滤权限和日期段 CSV 说明。
- 浏览器实走：摘要切换、图例、条形图、矩阵、日期点、CSV 下载、筛选、日期交换、空态、当前/期间分离、案件钻取与返回。覆盖率单日说明 5/5，失败通话 1 条、专业性 2 项、周敏专业性 1 项均与记录一致。这些是当前种子样例结果，不是产品固定值。
- 质检员和坐席直接访问 reports 路径分别回到有权页面，无报表 DOM / 导航。原始用户浏览器数据未重置；验收均在独立上下文执行。
- 1440×1000 四视图截图逐张查看；390×844 四视图没有整页横向溢出；趋势和明细在自身区域滚动。规则与通话列表抽查确认全局面板和标题调整没有破坏布局。
- 按 [Web Interface Guidelines](https://raw.githubusercontent.com/vercel-labs/web-interface-guidelines/main/command.md) 核对可见标签、语义页签、焦点、空值与数值可读性；本轮核心交互走查未出现页面脚本错误。自动化两次通用定位不精确已改为对应 DOM/角色定位，未将测试定位错误记为产品缺陷。

报表筛选、页签与钻取选择通过 Activity 在跨页返回时保留；刷新重新进入默认近 7 天概览，未新增可共享筛选链接。项目仍是浏览器状态驱动的高保真原型，无真实模型、实时服务端统计或生产认证承诺。

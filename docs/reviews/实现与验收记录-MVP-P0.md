## 已采纳决策

| 决策 | 实施规则                                                                                                                                     |
| ---- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| D01  | 仅本人最新已送达不利结论可正式申诉；撤回/不受理可重提，实质办结同版不无限重复；新不利版本可重提                                              |
| D02  | 改判证据不足，以依据不充分终止旧人员整改；补证另设责任人和期限，重新成立后新建整改                                                           |
| D03  | 两名质检员；申诉分派默认另一人；使用原复核人须填写同人原因，主管保留最终裁定                                                                 |
| D04  | 显示数量和明细，不显示按时完成率；保留首次逾期、原期限、有效期限、暂停与调整记录                                                             |
| D05  | `R-AC-003` 静默：默认 15 秒，3–60 整数；`R-INT-001` 业务：全部/账户查询/信用卡/转账汇款；`R-AL-001` 提醒：高风险/全部候选/关闭。其余规则只读 |

## 验证记录

本轮在 Node.js 26.8.1、Next.js 16.2.6 下验证。依赖使用已有 lockfile，pnpm 11.19.0。

- `pnpm typecheck`：通过。
- `pnpm lint`：通过。
- `pnpm build`：通过，首页可静态预渲染；业务数据仅在恢复当前演示身份后渲染。
- `pnpm test:workflow`：24 项通过，包含 T01—T18、正式申诉边界、同人核查、执行状态、资源新增、转派和核查完成状态。
- `pnpm verify:mvp`：检查端口、16 项目录、核心产物及工作流回归。

浏览器实际操作记录：

1. 主管发送实时提醒 → 坐席已读 → 模拟通话结束 → 质检员逐项复核 → 主管确认并下发整改 → 坐席接收、生成并提交整改后样例 → 质检员验收通过 → 主管结案，所有阶段均产生真实前端记录。
2. 主管受理 `AP-1033` → 默认由另一名质检员林悦核查 → 提交不成立意见 → 主管改判误报。结果为申诉办结、核查已完成、结论新增 V2、旧整改终止。
3. 修改静默阈值并发布新版本；新增业务知识条目、关联固定规则、检查并发布。草稿与生效版本均能查看。
4. 报表点击人工确认误报占比，下钻到同一组已确定自动候选，成功下载 CSV。
5. 切换为周敏后刷新，并直接访问主管报表与陈佳整改链接：仍为周敏、回到授权入口，页面无他人整改内容。
6. 390 × 844 手机视口：文档宽度为 390，无页面级横向溢出；导航抽屉正常；16 项目录可打开，Escape 关闭弹窗。桌面采用 1440 × 1050 核对。

验证中发现并修复：自动建单空标题回退、预警待办责任统计、抽查无发现/证据不足的持久化区分、刷新前的默认主管界面闪现、正常办结的申诉核查被误标为取消。

截图位于 `界面验收/`。截图与浏览器记录是界面核对证据；24 项测试是业务状态验证，二者各有作用，不把全部自动场景表述为逐项浏览器手工验收。

## 演示与后续边界

- 检测为预设执行结果；开始时冻结规则/资源快照，结束及重检作为显式场景事件。不接入真实 ASR、声纹、模型训练、音频上传流水线或 CTI。
- CALL-1041 使用本地语音合成素材，六段分别生成并按帧数校准时间；其他无音频样例明确提示缺失。原型无真实客户录音。
- 申诉初始跟进期限、观察要求和样例数量均为演示值；以连续时间计算暂停，不实现工作日日历或客户 SLA。
- 检查结果明确为预设场景，参数调整不声称提升模型效果；业务资源发布只影响后续示例检测。
- 状态保存在当前浏览器 localStorage。支持刷新、角色切换和同浏览器标签同步，不提供多人实时服务器协作或生产权限保证。
- 原始完整版文档保留在 `sources` 与原目录，只作来源。后续主要维护当前 PRD、图源及本记录。

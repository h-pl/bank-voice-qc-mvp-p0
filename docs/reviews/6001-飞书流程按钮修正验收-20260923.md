# 6001 飞书流程按钮修正与验收

2026-09-23。本轮目标是修改 6001 页面并核对全部业务流程节点。依据为实际读取的飞书 PRD（修订号 527）：主线、申诉两张 Mermaid，以及整改画板 M37fwPOtthCzZhbwXS1clr45nC1。本轮再次抓取与建议轮的原文一致。

## 本轮修改

1. 申诉页面的分发要求明确标为原处理结果，不再提示“接受整改后由主管补派”。当前申诉说明明确：不成立进入整改并沿用申诉核查质检员，不重复接受、重复指派。
2. 整改要求摘要使用当前任务的目标、标准、资料、样例数量、期限及核验人。原分发快照保留，不再覆盖本轮已调整的要求。
3. 仅待知悉的结果显示“结果知悉 / 待确认知悉”及当前坐席，不再同时显示“轮到我处理 / 当前无待办”。知悉不改变结论、不启动整改。
4. 直接整改的并行指派待办显示当前主管及“待指派核验人”，坐席仍可提交资料。暂停的整改不再产生不可执行的补派待办。
5. 未发现问题抽检的主管按钮统一为“确认抽检完成”；完整材料里的旧文案不再引导提交“证据不足”正式结论。
6. 申诉和整改退回核对弹窗使用与概览相同的主管退回依据，兼容旧数据只有事件记录而没有专用字段的情况。
7. 新增稳定 mock：CTX-EVIDENCE-INSPECTOR。林悦执行赵宁原复核的补件，只有独立补件权限；主管接收后交回赵宁。场景版本由 2 升至 3，47 个增至 48 个。增量迁移保存原对象和进度，备份键为 before-context-scenarios-v3；不重置用户数据。

## 节点与辅助操作边界

| 节点 | 业务动作 / 责任边界 |
| --- | --- |
| 主管初审 | 直接提醒并分发、确认误报并归档、转人工复核。无直接补件第四出口。 |
| 普通复核 / 质检员 | 提交核实结果、申请补证。资料不足继续核实，不作为新正式结论。 |
| 普通补证交接 | 质检员申请→主管安排执行人→执行人独立提交→主管接收→原质检员继续。与申诉补件分开。 |
| 主管确认复核 | 确认误报归档或非误报分发；有异议退回重新核实。无通用转派、延期、补件。 |
| 人工抽检 | 质检员提交抽检结果、登记发现；同通话符合条件才可关联已有问题。主管无发现确认完成、有发现确认分发，均可退回。 |
| 坐席已收到正式结果 | 接受并开始整改、不接受提交申诉；确认知悉不代替选择。 |
| 申诉指派 / 核查 | 主管指派；核查质检员提交意见、向坐席要求补件，并由该质检员接收。 |
| 申诉裁定 / 退回 | 主管确认或退回；质检员赞同重新核查，不赞同补依据给主管。成立撤销归档，不成立直接进入整改。 |
| 整改执行 | 坐席提交资料；直接分发且直接接受的路径可先提交、主管并行补派。其他来源继承质检员。 |
| 整改核验 / 最终审核 | 质检员不满足则列要求退坐席；通过交主管。主管确认完成或退回质检员。 |
| 整改主管退回 | 质检员赞同则补要求给坐席新一轮；不赞同则保留本轮资料补依据给主管。 |
| 已完成 / 归档 | 无原办理动作；保留查询。自动误报可记录规则优化反馈；本人可确认知悉结果。 |
| 转派与延期 | 主管仅在复核进行中/质检员核对意见阶段提供；最终确认阶段不提供。申诉非最终裁定阶段允许延期。 |
| 整改管理操作 | 活跃且未暂停、未进入主管最终审核或质检员回应阶段可调整要求/期限、转派已有核验人；直接来源未指派则补派。坐席申请调整要求的主管处理阶段保留对应动作。 |
| 草稿 | 在核实、核验弹窗内保存；通话中不提交正式核实结果，提供编辑草稿。不存在“更多操作”折叠。 |

上述辅助操作是本轮核对后的页面实现边界；飞书简图未逐一展开的补证、期限管理按同文档角色及状态契约解释。未扩大简图中的主管最终确认权限。本轮未写入飞书。

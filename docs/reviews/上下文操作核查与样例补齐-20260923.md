# 上下文操作核查与样例补齐

日期：2026-09-23。目标：6001 工作台。依据：三张已确认流程图及 PRD 7.5–7.7。

## 核查范围

通话、预警、复核与抽检、申诉、整改、补件、规则/策略、资源，以及报表钻取、通知和提交后查看记录入口。核对详情、主按钮、表单字段、命令权限和结果去向；有效办理动作直接展示，不使用“更多操作”折叠。

## 修正

- 主管确认阶段仅确认或退回；证据不足独立安排补证。确认表单保留质检原结论。
- 申诉核查人发起/接收补件；裁定只确认已提交结论或退回。使用申诉成立/不成立术语。
- 整改审核只允许确认或退回，不旁路改标准/转派；新流程资料不足退坐席并保留上一轮材料。
- 暂停、终态、无可关联对象、不属于当前责任人时不展示无效动作。已分发/归档问题不从跟进入口重启。
- 未结束通话保留编辑草稿；保存后可恢复记录。转派排除原责任人，继任者重新核查。
- 打开及提交时校验动作可用性；未保存退出有保护。
- 修复成功提示按钮被 pointer-events 禁止点击的问题；完成反馈定位新生成事项或补件所属事项；无效资源/策略深链不再显示其他对象的按钮，归档配置不可编辑。
- 补件状态区分待提交与待接收，责任人同步更新，下一步操作区可直接提交/接收补件；后续样例通话开始、结束与时长一致。

## 分拣入口补漏

主管对待分拣预警仅有直接分发、确认误报、转人工复核三个业务出口，不提供“要求补充材料”。该旧通用入口已从权限及命令层移除；历史补件仍可接收并继续，现有进度不重置。资料不足由质检员在复核中申请补证，主管再安排执行。旧版结果跟进、主管直接向申诉索要补件也不再作为当前界面入口。

新增精确按钮集合回归：同时检查通话中/已结束预警只有三个出口，并验证先转复核后补证仍可办理。此前仅检查“显示的动作可执行”不能证明它符合流程图，本次补上流程出口约束。

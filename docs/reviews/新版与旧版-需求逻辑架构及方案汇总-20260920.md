# 新版与旧版：需求、逻辑、架构及方案汇总

日期：2026-09-20。来源：本任务两轮对比及用户“按照建议方案”指示。
新版指 5001 当前 MVP（包含未提交的 UI 迭代）；旧版指 5002、进入 MVP 前的 V4.11.0-private.1（92ae9aa）。旧版后续需求文档与其已发布代码分开评价。

## 结论

以新版为迭代基础，吸收旧版的业务表达与职责分工。当前建设客户日常质检工作面；真实模型、服务端、项目交付后台和新增组织角色分阶段建设。原型允许预设结果和浏览器状态，不将模拟发布、评测 API 或演示权限当成生产能力。

## 最终对比表

| 维度 | 新版 | 旧版 | 采纳方案 |
| --- | --- | --- | --- |
| 产品范围 | 三角色七模块，主线集中 | 客户生产台与项目后台、十角色，范围完整 | 新版客户作业为当前范围，项目交付与评测独立工作面后置 |
| 菜单 | 简洁，缺少统一工作台 | 工作台完整，有工单2/3/4试验入口 | 新增轻量工作台，只保留一套复核工单 |
| 角色 | 主管直派，链路短但职责集中 | 班组、专家、运营等分工完整 | 保留三角色主路径，预留班组与专家职责，按实际需要启用 |
| 模块职责 | 风险、复核、申诉、整改独立 | 文档已澄清，旧页面仍有混合方案 | 分诊、核查、纠错与改善各自独立状态，关联展示 |
| 布局 | 统一作业框架，仍有多层容器 | 分区清楚，但说明和卡片多 | 作业三栏、通话资源表格、报表分析；统一语言而非统一布局 |
| 首屏滚动 | 操作集中，固定区仍挤正文 | 页面长，操作材料可能下沉 | 摘要、依据、责任、主动作优先；长材料按需预览 |
| 信息表达 | 简洁，编号与笼统预览偏多 | 业务含义充分，术语和制度说明偏多 | 业务名称优先，编号次要，辅助解释进入 info |
| 筛选 | 搜索、展开、标签、分页较完善 | 分类直观，部分只是展示 | 新版机制，保留筛选与选中对象 |
| 责任与下一步 | 当前责任期限明确 | 当前与下一节点表达好 | 新版紧凑结构加提交去向与等待对象 |
| 材料 | 弹窗减少滚动，材料概括过强 | 名称、用途、已固化/待补充清楚 | 旧版清单表达加新版预览 |
| 复核结论 | 成立/误报/不足、无需整改、抽查、逐项处置 | 主管控流明确，部分出口未实现 | 沿用新版；结论与处置分开 |
| 申诉整改 | 版本、补件回流、暂停恢复、轮次较完整 | 角色协作充分，联动部分待补 | 新版状态机制，按需引入旧版角色；材料核验与效果验收分开 |
| 规则参数 | 当前值、范围、版本和就地编辑直接 | 适用场景、命中动作、影响表达充分 | 新版编辑加旧版业务边界；提交核对差异与影响 |
| 业务资源 | 内容引用版本清楚，不便横向比较 | 分类表格便于比较，部分保存仅提示 | 分类表格入口，完整内容与引用详情；首期三类资源 |
| 发布关系 | 资源发布自动升级关联规则引用 | 文档要求审批与回归，代码不完整 | 发布资源与切换引用分开，历史批次保持快照 |
| 报表 | 数据计算、筛选、callout、下钻真实联动 | 管理指标表达好，当前主要静态展示 | 新版计算和联动，吸收管理视角，区分各业务对象分母 |
| 代码架构 | 分拆初步完成，工作流集中 | 大页面混合多页面和动作 | 继续整理新版，按业务模块拆分，共享校验和事件契约 |
| 状态权限 | 统一 State、去重、版本校验，前端演示 | 多组 localStorage 状态协调，演示角色丰富 | 统一动作入口；真实阶段用服务端授权、事务、冲突控制 |
| 模型交付 | 预设检测与浏览器状态 | 有评测部署页面，未证明真实交付 | 原型与真实接入、评测、容量、权限分开验收 |

## 目标结构

- 工作区：工作台（当前角色待办、超时、需关注变化）。
- 质检作业：风险预警、复核工单、申诉与整改、通话记录。
- 策略与资源：质检规则、业务资源。
- 分析：质量报表。
- 业务核心：通话与证据 → 问题 → 复核与结论 → 申诉／整改。
- 共享机制：权限范围、责任交接、期限、版本、追加事件、待办、统计。
- 后续项目工作面：规则包、测试集、评测、交付。

## 不可混淆的业务约束

1. 通话是证据载体，问题是判断对象，工单是处理任务。
2. 复核意见与主管结论分开。申诉绑定结论版本，整改绑定成立结论及标准版本。
3. 申诉与整改独立；有效申诉提交暂停关联整改，裁定后恢复、调整或终止，保留期限记录。
4. 已读不是任务完成，检测失败不是无风险，证据不足不是误报。
5. 资源新版本发布后不自动切换规则；逐规则确认引用变化后用于新检测。历史批次不变。
6. 原型中的三个角色不代表最终权限模型；职责增加不得只靠显示新菜单完成。

## 实施顺序与本轮范围

1. 当前 6001：轻量工作台、资源分类表格、案件摘要与材料状态、责任去向、规则引用独立切换，统一菜单表达与正文层级。
2. 同步更新业务规则、测试、设计与交互文档，验证角色范围、重复提交、旧版本、统计一致性。
3. 按业务边界逐步整理代码，优先抽出本次资源目录和发布模块，不做无关大改。
4. 班组、专家、项目后台按需扩展；服务端权限、数据库事务、异步检测和真实评测留真实试点阶段。

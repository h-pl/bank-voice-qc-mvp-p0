## 3. 验证结果与实际边界

- `pnpm lint`、`pnpm build` 通过，构建内 TypeScript 检查通过；独立 `pnpm typecheck` 在本轮首轮实现时通过。
- 最终 `pnpm verify:mvp` 通过：16 项目录、独立 5001 端口、核心产物与 50/50 业务回归。原有 38 项加 lifecycle.test.mjs 的 12 项；不是仅断言按钮存在。
- 浏览器在 1440×1000 实际完成：草稿保存→刷新→重开，标准 V1→V2 后核对→提交，坐席回件→主管接收→原质检员继续，提醒已读→反馈→刷新，终止补件只读。390×844 验收表单无页面横向溢出；Esc 关闭恢复“验收处理”按钮焦点。
- 正式通过/不通过/样例不足、暂停限制、转派失去权限、旧草稿确认与终止四种组合有执行层回归；本轮浏览器没有穷举所有业务组合。自动化个别定位初次使用通用名称不匹配，查看 DOM 后修正；不将定位超时计为业务缺陷。
- 依据 [Web Interface Guidelines](https://raw.githubusercontent.com/vercel-labs/web-interface-guidelines/main/command.md) 核对表单名称、可见反馈、焦点与减少动态效果；沿用既有动效，本轮不新增动画依赖。React 采用表单打开时初始化和事件提交，不以额外 Effect 复制草稿状态。

兼容读取保留原存储键。旧验收文字缺少轮次等元数据时不能冒称已验证旧标准，只作为待核对参考；已经丢失的旧历史无法恢复。角色切换、预设转写和检测、样例材料及浏览器持久化仍是原型实现，没有真实银行接入、模型测评或生产认证承诺。
